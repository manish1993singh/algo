## 🔍 The Efficiency Issue
Your current solution uses nested loops: a for loop to iterate through each booking, and an inner for loop to iterate across the range of flights.

* In the worst-case scenario, every booking covers all n flights.
* If you have B bookings and n flights, the time complexity becomes $O(B \times n)$.
* Given the constraints where both B and n can be up to 2 × 10⁴, the total operations could reach 4 × 10⁸, which is too slow for the standard 1-second execution limit.

## 💡 The Difference Array Trick
The core idea of a Difference Array is to log only the changes (the boundaries) in O(1) time, and then compute the final prefix sum at the very end in O(n) time. Instead of updating every single element in the range [start, end]:

   1. Add the seats to the start position.
   2. Subtract the seats from the end + 1 position (to cancel out the effect after the range expires).

## 🚀 Optimized O(n + B) Solution

def find_seat_opt(arr, n):
    # Create a difference array of size n + 1 to handle end + 1 boundary safely
    diff = [0] * (n + 1)
    
    for start, end, seats in arr:
        # Convert 1-based indexing to 0-based indexing
        diff[start - 1] += seats
        diff[end] -= seats
        
    # Reconstruct the original array by running a prefix sum
    result = []
    current_seats = 0
    for i in range(n):
        current_seats += diff[i]
        result.append(current_seats)
        
    return result

This reduces the total operations from 400 million down to just around 40,000!
